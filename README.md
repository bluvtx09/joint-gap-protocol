# Joint Gap Protocol

시뮬레이터와 실물 로봇 관절 사이의 오차를 **성분별로 분해**하는 절차와 도구.

시뮬이 실물과 다르다는 건 다들 안다. 그런데 **무엇 때문에 다른지**를
재현 가능한 방식으로 답하는 표준 절차는 잘 보이지 않는다.
이 저장소는 그 절차를 만들어보려는 시도다.

## 지금까지 나온 것

공개 데이터 분석 결과다. 자세한 해석은
[`findings/public-data-first-findings.md`](findings/public-data-first-findings.md).

### 널리 쓰이는 공개 시뮬레이터에 액추에이터 성분이 통째로 빠져 있다

| | 명령 토크 대비 실제 토크 오차 |
|---|---|
| 시뮬 | **0.000000 N·m** |
| 실물 | **0.031 N·m** (명령의 19.8%) |

시뮬 쪽 잔차가 부동소수점 오차도 없이 정확히 0이다.
"명령한 토크가 곧 관절에 걸린다"고 가정한다는 뜻이다.

### 그 빈자리는 마찰 모델로 메워지지 않는다

점성 마찰로 설명되는 건 잔차의 **4.6 ~ 6.0%뿐**이다.
"마찰항을 넣으면 되겠지"는 거의 도움이 안 된다.

### 식별되는 물리량이 여기 궤적에 따라 달라진다

같은 실물 로봇, 같은 관절, 속도 구간까지 맞춰 비교했는데도

| 관절 | 폐루프에서 뽑은 점성계수 | 개루프에서 뽑은 점성계수 |
|---|---|---|
| 0 | +0.00117 | +0.00103 |
| 1 | +0.00132 | +0.00184 |
| 2 | **−0.00082** | **+0.00249** |

관절 2에서 부호가 뒤집힌다. 음의 점성 마찰은 물리적으로 불가능하다.
**절차 없이 데이터만 있으면 물리적으로 불가능한 값이 나온다**는 뜻이다.

### 데이터가 있다고 갭을 잴 수 있는 건 아니다

시뮬과 실물의 각도 차이가 **t=0에서 이미 0.345 rad** 벌어져 있었다.
초기 조건이 안 맞춰져 있어서, 이 차이는 모델 오차가 아니다.

로그를 갖고 있어도 그냥은 못 쓴다. 어떻게 찍어야 하는지가 먼저다.

## 구성

```
analysis/
  reproduce_public.py   공개 데이터 다운로드 + 위 결과 재현
  analyze_gap.py        실측 데이터에서 성분별 갭 기여도 계산
hardware/
  sweep_stiffness.py    시뮬 안에서 강성×궤적별 민감도 순위표 생성
  spring_selector.py    직렬 탄성 관절의 스프링·반경 조합 선정
  experiment_form.xlsx  실험 데이터 기록 양식
findings/
  public-data-first-findings.md
protocol/
  (작성 중)
```

### `analyze_gap.py`가 하는 일

1. 데이터시트 값만 넣은 시뮬과 실물 궤적을 비교 → 기준 갭
2. 성분을 하나씩 실측값으로 바꿔 끼우며 갭이 줄어드는 양을 측정
3. 줄어든 양이 그 성분의 기여도. 이걸로 순위를 매긴다
4. 전부 바꿔도 남는 갭을 **노이즈 몫**과 **구조 몫**으로 분리

4번이 핵심이다. 구조 잔차가 크면 파라미터를 더 정확히 재도 소용없다는
뜻이고, 그 판단 자체가 결과다.

**유의성 문턱을 적용한다.** 반복 시행 간 기여도 표준편차의 2배를 넘지
못하는 성분은 순위에서 빼고 "구분 불가"로 보고한다. 이게 없으면
노이즈에 순서를 매기게 된다.

## 진행 중인 실물 실험

관절 강성을 독립변수로 두는 1자유도 직렬 탄성 관절 테스트베드를
준비하고 있다. 부 질문은 **"관절 강성을 바꾸면 갭을 지배하는 성분의
순위가 바뀌는가"**다.

시뮬레이션에서는 세 여기 궤적 모두에서 순위가 바뀌는 것을 확인했다.
실물 검증은 아직이다.

설계에서 특히 신경 쓴 부분:

- **변형각을 고정하고 토크를 강성에 맞춘다.** 토크를 고정하면 강성을
  올릴수록 측정 정확도가 나빠져서, 순위 변화가 물리 때문인지 측정
  때문인지 구분할 수 없게 된다
- **같은 강성에서 토크만 바꾼 대조군**을 별도로 측정한다. 위 설계가
  들여오는 새 교란 변수를 빼내기 위해서다
